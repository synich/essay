# 线程执行的汇编过程
## 线程的参数怎么传递
线程的执行体对应指令段，把指令地址加载到IP指针就可以，那么参数要怎么传递给线程呢？看pthread_create的定义，可以传入一个void\*指针，说明线程支持传参，考虑到线程生命周期，这个void\*参数自然是放在堆上最稳妥。如果要传多参数，用struct包一层就够了。

这个传递的线程函数的参数，其实和普通函数并没有区别，在x64-Linux体系下，把void\*的值（地址）放到RDI寄存器，新的线程就能获取到。所以线程只是启动过程会多出clone动作，IP/栈指针/参数传递的逻辑是完全一样的。

## C++的lambda与thread
首先要理解清楚，lambda所代表的函数执行体和thread对应的线程执行环境是分开的。特别是线程池模型中，一个线程可以在不同时间执行不同的函数。
C++将二者都封装成对象，lambda对象包括执行逻辑和捕获变量，对应编译器构造的匿名类创建出的无名变量；而thread对象则对应操作系统的线程。线程池模式下，把lambda对象压入queue，线程池中再以mutex+condition_variable方式，等待空闲的线程后，从queue中取回lambda对象并执行。伪码如下

```
for(;;) {
  {
  unique_lock<mutex> m_; // 自动作用域
  cv_.wait(m_);  // 等锁
  task = std::move(tasks_.front());
  tasks_.pop();
}
  task(); //出mutex作用域，执行某个函数逻辑。完成后再次进行循环
}

~析构  {
  cv_.notify_all();
  for (auto &w: workers_) w.join();  // 一定要逐线程.join()防止被terminate
}

enqueue(std::function<void()> f) {
  {unique_lock<mutex> m; tasks_.push(std::move(f));}
  cv_.notify_one();  // 唤醒一个线程
}
```
