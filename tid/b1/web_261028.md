# Web的图像处理

浏览器原生支持图像的缩放，整个过程很值得记录

## 转换过程涉及的类型

一张硬盘上的图片，加载到浏览器然后缩放，并最后上传中间要经过多个类型转换

1. File: 是Blob的唯一标准子类，增加了文件的元信息，和磁盘文件交互的必经之路
2. ImageBitmap: BMP格式图片在内存/显存的表示，无法序列化和直接导出
3. Blob(Binary Large Object): 图片缩放后再编码成jpeg/png的二进制对象
4. String: 严格的说是语义化的DataUrl(RFC 2397)，是自包含自描述且最普遍接受的二进制表示法

File对象来自HTML中type=file的input元素，是磁盘文件的直接映射。为了编辑图片，用window.createImageBitmap方法将文件数据转换成bmp格式。

编辑bmp图片要用到canvas的2d模式，使用drawImage将bmp调整为想要的分辨率，再用toBlob将canvas中的bmp编码成指定的mime格式。

最后就是Blob转成传输给服务端的DataUrl格式，定义如下

```
data:[<mediatype>][;base64],<data>
```

`data:`是固定头，类似`file:`，然后是Mime类型，默认text/plain;charset=US-ASCII；再是可选的base64标记，如果省略则用urlencode编译。DataURL最初的设想产生于1995年，于1998年标准化，比Blob的出现(2010年)要久远得多。是Blob出现之前JS表示二进制数据的唯一格式

看似需要4种类型很啰嗦，但每一个都有不可替代的作用

最后再补充整个环节的可选对象ObjectURL，它的作用是`<img>`标签预览缩放后图片，img.src不能指向Blob，需要通过URL.createObjectURL把Blob转为img.src能接受的格式才能使用
